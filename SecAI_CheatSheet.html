CompTIA SecAI+ (CY0-001) — One-Page Cheat Sheet

60 questions · 60 min · pass 600/900 · Domains: Concepts 17% · Securing AI 40% · AI-Assisted 24% · GRC 19%

Domain 1 — Basic AI Concepts 17%

TransformerSelf-attention architecture behind LLMs.
LLM vs SLMLarge (general, cloud) vs Small (narrow, on-prem → less leakage).
ML typesSupervised · Unsupervised · Reinforcement.
GANGenerator vs discriminator → synthetic data / deepfakes.
OptimizePruning (drop weights) · Quantization (lower precision) · Epoch (one data pass).
PromptingZero/one/multi-shot; system vs user prompt separation.
RAGRetrieve docs via embeddings in a vector store → inject into prompt; cuts hallucination.
LineageOrigin/history of data → detects poisoning, proves integrity.
HITLHuman-in-the-loop reviews high-risk AI output.
Lifecycle: collect → prep → select → evaluate → deploy → monitor (+ feedback & oversight).

Domain 4 — Governance, Risk & Compliance 19%

EU AI ActRisk tiers: Unacceptable (ban) · High · Limited · Minimal.
NIST AI RMFFunctions: Govern · Map · Measure · Manage.
ISO 42001AI Management System — "ISO 27001 for AI".
OECDInternational AI principles.
AI CoECenter of Excellence sets policy/roles/standards.
Shadow AIUnsanctioned AI use → leakage, compliance risk.
Responsible AI: fairness · reliability/safety · transparency/explainability · privacy · inclusiveness · accountability · training.
Also: data sovereignty/residency · private vs public model governance · 3rd-party compliance.

Domain 3 — AI-Assisted Security 24%

Defensive AI: IDE/CLI/browser plugins · chatbots · MCP servers · vuln analysis · automated pentest · anomaly detection · incident automation · fraud detection.
AI-enabled attacks: deepfakes (impersonation/disinfo) · automated recon · social-engineering boost · obfuscation · auto payload/malware generation.
Automation: low/no-code · IR ticketing · change approvals · deploy/rollback · agent orchestration · CI/CD (code scan, SCA, test).

Domain 2 — Controls & Frameworks 40%

Threat modeling: OWASP LLM Top 10 · OWASP ML Top 10 · MITRE ATLAS · MIT AI Risk Repo · CVE AI WG.
Gateway controls: prompt firewall · rate/token limits · input quotas · modality limits · endpoint access.
Encryption: in transit · at rest · in use (TEE).
Data: anonymize · classify/label · redact/mask · minimize.
Least privilege across models · data · agents · APIs · networks.
Monitor: log+sanitize prompts/responses · confidence · cost · anomaly · audit hallucination/bias.

Domain 2 — Attacks → Defenses 40%

Prompt injectionMalicious input overrides system prompt → firewall, validate, separate prompts, least priv.
Data poisoningCorrupt training data → provenance, integrity checks, trusted sources.
Model poisoningTamper weights → signed models, supply-chain vetting.
JailbreakBypass guardrails → layered guardrails, output filter, red-team.
Adversarial (FGSM/PGD)Perturbed input → adversarial training, robustness testing.
Model inversionRebuild training data → differential privacy, limit confidence.
Membership inferenceWas record in training? → diff privacy, less overfit.
Model theftClone via queries → rate limit, monitor, watermark.
Model DoSResource exhaustion → rate/token/size quotas, cost track.
Insecure outputUnsanitized output → injection; encode/validate downstream.
Excessive agencyOver-permissioned agent → least priv, HITL, scoped tools.
Supply chainBackdoored model/dep → vet, SCA, signed artifacts.
Data disclosureLeaks PII → minimize, redact, output filter, RAG access ctrl.

Exam tips

  • Domain 2 = 40% — master attack ↔ defense pairings.
  • Memorize frameworks cold: EU AI Act tiers, NIST RMF (G/M/M/M), ISO 42001, OWASP LLM Top 10, MITRE ATLAS.
  • Encryption-in-use and least privilege across all AI components are favorite answers.
  • PBQs: pick the right control for a named attack/scenario.
